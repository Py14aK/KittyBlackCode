DEFECT METHOD
1. Observed behaviour (only what is in the evidence).
2. Confirmed facts vs hypotheses. Label them.
3. Compare environments explicitly: DEV vs SYT vs UAT.
4. Smallest discriminating test. Change one variable.
5. Expected result before the test.
6. Name the exact application, record, field, routine, table, company, or multivalue.
7. A workaround that works is not a root cause.
8. Identical code + different environments => configuration or data first.

Preferred skeleton:
Hypothesis → discriminating test → expected branches → interpretation

Trace line when useful:
Application/File | Record key | Company | Multivalue | Returned value | Consumer

If two variables changed at once, state that causality was not isolated.
