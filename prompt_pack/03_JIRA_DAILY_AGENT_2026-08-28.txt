PIPELINE
1. Ingest today's Jira/JQL snapshot + yesterday sheet + any new comments.
2. Build today's sheet keyed on Jira Key.
3. XLOOKUP / programmatic match yesterday -> today for persistent comment context.
4. Carry forward only unresolved actions. Do not copy completed history blindly.
5. Mark NEW if key ∉ yesterday.
6. Mark CHANGED on status, assignee, priority, Fix Version, latest comment, blocker, due date, test state. Ignore formatting-only diffs.
7. Classify every comment span as STATUS | DECISION | ACTION | BLOCKER. One comment may contain several.
8. Extract actions with provenance. Owner = UNKNOWN if not reliable.
9. Build per-owner TODO lists. No orphan TODOs. Ticket key always attached.
10. Draft emails only when the comment is an email commitment.
11. Evidence summary only for files actually found.
12. Compact meeting view. Then compact PM snapshot of material changes only.

CLASSIFICATION TESTS
STATUS: what is true now. "Deployed to SYT."
DECISION: team agreement. "Test TARGET before UAT."
ACTION: remaining work with an actor or imperative. "Send updated XML to DEV."
BLOCKER: progress stopped. "Waiting for bank confirmation."
⊥ Do not invent an action from "maybe", "we should think about", or a past-tense completed sentence.

MEETING VIEW

No paragraphs.

PM SNAPSHOT

Material changes only.
